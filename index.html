02 / HOW THEY TALK TO EACH OTHER

The four architectures you'll build in real jobs.

Services are useless in isolation. This is how an organization wires them — VPC-to-VPC, API routing, event fan-out, and the ML/AgentOps pipeline.

FLOW 01

The production web request

DNS → EDGE → COMPUTE → DATA
Route 53DNS
CloudFront310 edge PoPs
ALBTLS ends here
Auto Scaling2–40 EC2
RDS Multi-AZprivate subnet
Why this order: DNS resolves first, the edge caches static assets, the ALB terminates TLS and only forwards dynamic calls.
Security layering: EC2 and RDS live in private subnets — nothing on the internet can reach them directly, only via the ALB's security group.
Failure story: health checks mark instances unhealthy, Auto Scaling replaces them, Multi-AZ fails the database over automatically.
FLOW 02

Serverless API — API Gateway → Lambda → DynamoDB

AUTH → ROUTE → EXECUTE → STORE
CognitoJWT auth
API GatewayPOST /orders
Lambdabusiness logic
DynamoDB<10ms reads
How the request routes: API Gateway matches POST /orders to a route, validates the Cognito JWT, then invokes Lambda and returns its JSON response.
IAM is the wire: Lambda doesn't "connect" to DynamoDB with credentials files — it assumes an execution role whose policy allows exactly one table.
Async side-channel: Lambda publishes an event to EventBridge, which fans out to SQS workers + SNS notifications — the API response never waits for them.
FLOW 03

VPC-to-VPC & hybrid connectivity

ON-PREM ⇄ CLOUD · VPC ⇄ VPC
On-prem DCyour racks
Direct Connectprivate fiber
Transit Gatewayhub & spoke
VPC-A / VPC-Bper team · per env
2 VPCs, same region: use VPC Peering (cheap, direct, non-transitive). 5+ VPCs: use Transit Gateway — one hub, every spoke routes through it.
Private SaaS access: PrivateLink exposes a service into another account's VPC without touching the public internet.
Hybrid: Direct Connect gives a dedicated line to the office; Transit Gateway then makes every attached VPC reachable from on-prem using route tables + BGP.
FLOW 04

The MLOps / AgentOps pipeline

COMMIT → BUILD → DEPLOY → OBSERVE → ROLLBACK
CodePipelinegit push
CodeBuildtrain / build
ECRimage / model
SageMakerendpoint
Bedrock Agentprod alias
CloudWatchevals + rollback
MLOps: SageMaker Pipelines / Step Functions retrain on schedule, registry versions models, endpoints deploy blue-green so rollback is one click.
AgentOps: Bedrock Agents get aliases (DRAFT → PROD), every trace lands in CloudWatch — hallucination rate, tool-call failures and latency become your SLOs.
Guardrails: GuardDuty + WAF + IAM sit underneath the whole pipeline; EventBridge fires on model-drift alarms and re-triggers the build stage.
